# Antigravity Rules: Закреплённые регламенты и правила разработки

Этот документ является **несменяемым якорем правил** для всех разработчиков и ИИ-агентов, работающих с проектом.

---

## 1. Контекст и архитектура проекта

- **Название**: PRISM-LLM Translator API (`transneft-news-translator`).
- **Назначение**: Изолированный stateless микросервис машинного перевода новостей с русского языка на английский (RU→EN) для интеграции с внешним веб-порталом 1С-Битрикс через REST API.
- **Технический стек**: Python 3.12, FastAPI, Pydantic (v2), Pytest, pymorphy3, mlx-lm / LiteLLM.
- **Паттерн**: **Controller — Service — LLM Client**:
  - Роутеры (Controller): `src/backend/api/v1/`
  - Валидация и схемы: `src/backend/api/schemas.py`
  - Бизнес-логика и оркестрация (Services): `src/backend/services/`
  - Изолированный клиент LLM: `src/backend/services/llm_client.py`

---

## 2. Stateless & Конфигурация

- Сервис строго **Stateless**.
- Использование баз данных **запрещено**.
- Вся конфигурация загружается строго через `.env` (Pydantic Settings `src/backend/config.py`).
- Обязательно наличие образца `.env.example` в корне.

---

## 3. Правила ведения Git Workflow и коммитов

### 3.1. Создание веток
- Все новые ветки отпочковываются **ТОЛЬКО от `develop`**.
- Формат названия ветки: `<тип>/<TICKET_ID>-<краткое_описание>`
  - `feature/` — новый функционал (пример: `feature/AICHAT-001-translation-endpoint`)
  - `bugfix/` — исправление ошибок (пример: `bugfix/AICHAT-002-fix-cors`)
  - `hotfix/` — срочное исправление (отпочковывается от `main`)
- **Прямые коммиты в `develop` и `main` ЗАПРЕЩЕНЫ.**

### 3.2. Правила коммитов
- **Один коммит — одно логическое изменение** (атомарность).
- Сообщение коммита начинается строго с номера тикета:
  `AICHAT-XXX: <Описание логического изменения на русском языке>`
  *(Пример: `AICHAT-001: Добавлены Pydantic v2 схемы для TranslationRequest`)*.

## 4. Организационные правила структуры репозитория

### 4.1. Чистота корня
- В корне репозитория находятся **только целевые системные файлы**:
  `.env`, `.env.example`, `.gitignore`, `Dockerfile`, `docker-compose.yaml`, `pyproject.toml`, `README.md`, `CHANGELOG.md`, `TODO.md`, `AGENTS.md`, `Antigravity_rules.md`.
- Никакой свалки временно созданных скриптов в корне!

### 4.2. Распределение поддиректорий
- `src/backend/` — исходный код микросервиса.
- `configs/` — конфигурационные файлы и рантайм-словари (`configs/glossary/`).
- `demo/` — скрипты для демонстрации (`demo/demo_live.py`, `demo/demo_it_abbreviations.py`, `demo/demo_local_translation.py`).
- `docs/` — документация, OpenAPI спецификации (`docs/api_contract.json`), методология и Mermaid-диаграммы (`docs/assets/`).
- `tests/` — автотесты Pytest.
- `archive_unneeded/` — исторические исследовательские архивы вне активного кода.

### 4.3. Правило несохранения / неудаления файлов
- ИИ-агенты **НЕ удаляют** файлы проекта самостоятельно.
- Все файлы перераспределяются по соответствующим целевым директориям.
- Окончательное решение об удалении файлов принимает **только пользователь**.

---

## 5. DevOps, Безопасность и Тестирование

- **Контейнеризация**: Приложение контейнеризируется через `Dockerfile` и `docker-compose.yaml`.
- **Корпоративные сертификаты**: В `Dockerfile` обязательно использовать аргументы `ARG NEXUS_CERT` и `ARG PYPI_INDEX_URL`.
- **Авторизация**: M2M-авторизация по заголовку `X-API-Key` через `hmac.compare_digest`.
- **Тестирование (TDD)**: Любой функционал покрывается автотестами в директории `tests/`.
