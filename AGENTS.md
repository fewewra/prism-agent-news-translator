# AGENTS.md — Инструкции и регламенты разработки

Документ описывает технический стек, архитектурные требования и стандарты разработки микросервиса.

---

## 1. Контекст проекта
Разработка изолированного stateless микросервиса машинного перевода (RU→EN) для интеграции с внешним веб-порталом 1С-Битрикс через REST API.

---

## 2. Технический стек
- **Язык**: Python 3.12
- **Фреймворк**: FastAPI
- **Валидация**: Pydantic (v2)
- **Тестирование**: Pytest
- **Управление зависимостями**: `pyproject.toml` (`pip` / `uv`)

---

## 3. Архитектурные правила
- **Паттерн**: Controller — Service — LLM Client:
  - Роутеры (Endpoints): Строго в `src/backend/api/v1/`
  - Схемы: `src/backend/api/schemas.py`
  - Бизнес-логика: Препроцессинг словаря (`pymorphy3`), формирование промпта — в `src/backend/services/`
  - Клиент LLM: Взаимодействие с LiteLLM / MLX изолировано в `src/backend/services/llm_client.py`

---

## 4. State & Storage
- Сервис строго **Stateless**.
- Базы данных **запрещены**.
- Вся конфигурация загружается через `.env` (`src/backend/config.py`).

---

## 5. DevOps & Security
- Приложение контейнеризируется (`Dockerfile` и `docker-compose.yaml`).
- В `Dockerfile` обязательно использовать аргументы (`ARG NEXUS_CERT`, `ARG PYPI_INDEX_URL`) для проброса корпоративных сертификатов (Nexus/PyPI Транснефти).
- M2M-авторизация выполняется по заголовку `X-API-Key` (`src/backend/dependencies.py`).

---

## 6. Testing (TDD)
- Любой новый эндпоинт сначала покрывается тестами в директории `tests/`.

---

## 7. Правила версионирования, ведения Git проекта, создания веток и коммитов

### 7.1. Создание веток:
- Все новые ветки отпочковываются **ТОЛЬКО от `develop`**.
- Формат названия ветки: `<тип>/<TICKET_ID>-<краткое_описание>`
- Допустимые типы:
  - `feature/` — новый функционал (пример: `feature/AICHAT-001-translation-endpoint`)
  - `bugfix/` — исправление ошибок (пример: `bugfix/AICHAT-002-fix-cors`)
  - `hotfix/` — срочное исправление (отпочковывается от `main`)

### 7.2. Правила коммитов:
- **Один коммит — одно логическое изменение**.
- Сообщение коммита начинается с номера тикета (пример: `AICHAT-001: Добавлена Pydantic схема для TranslationRequest`).

---

## 8. Организация файлов репозитория
- В корне репозитория поддерживается максимальная чистота.
- Демонстрационные скрипты размещаются строго в `demo/`.
- Документация и диаграммы размещаются в `docs/` и `docs/assets/`.
- Файлы **НЕ удаляются** ИИ-агентом; их перераспределение согласовывается с пользователем.
